# ScoreIR minimal schema - M0-005 implementation note (DRAFT, NON-FROZEN)

- Status: **Draft / non-frozen**. This is the M0-005 vertical slice
  (`core/score/scoreir.{h,cpp}`, the public draft ScoreIR schema under
  `schemas/score/`, the golden fixture, and the scoped `scoreir` harness
  commands). It is **not** part of the Frozen Baseline (`spec/v0.1/`) and does
  not modify it. Scope is explicitly limited to minimal ScoreIR source facts:
  NO Geometry/anchor, NO Performance/transform, NO Jianpu, NO model/UI/storage
  truth, NO float/seconds/ticks, NO generic MusicXML AST as core truth.
- Validation owner: orchestrator (this lane's project checks are
  `dev.ps1 build|test|verify scoreir`).

## 1. Instance identity

- An **instance** binds via `$schema` (exactly
  `choirloom:score/scoreir/0.1.0`) and MUST NOT carry `$id`: `$id` is the
  schema DOCUMENT's identity only. The core rejects instances that carry
  `$id` (`schema-binding-mismatch`).
- The score's own stable `EntityId` is `scoreId`; it is an entity identity,
  never an entity reference target.

## 2. Document model (source facts only)

- The document carries a stable `EntityId` for the score and for every
  referencable entity. `Part`, `Staff`, `Voice`, `PerformerRole`, `Measure`,
  and `Event` are DISTINCT collections with explicit typed ID references
  (`partRef`, `staffRef`, `voiceRef`, `measureRef`, `roleRefs`). The score
  identity is its own `Score` kind: references can never resolve to it
  (a `staff.partRef == scoreId` is mistyped).
- `PerformerRole` is extensible (never an SATB enum); a note's `roleRefs`
  permits multiple roles (shared-role events) and must be non-empty and
  duplicate-free.
- Parts are typed and this draft is **CHORAL-ONLY**: `type` must be `"choral"`;
  accompaniment parts are a future minimal variant (rejected here with
  `unsupported-part-type`, matching the frozen M4 boundary).
- Event source musical time uses the existing canonical `RationalTime` ONLY:
  `measureRef` + non-negative `offset` + positive `duration`. No floats,
  seconds, or ticks.
- `Measure` stores a canonical exact `actualDuration` RationalTime (positive);
  a pickup/incomplete measure carries its true (incomplete) duration.
- Written pitch distinguishes `written` spelling (letter + accidental +
  octave), `displayAccidental`, and `sounding` pitch (letter + accidental +
  octave) - so F# vs Gb are distinct spellings with the same/different
  sounding register made explicit.

## 3. Tagged event variants (Opaque/Unsupported are first-class)

Events are tagged variants (`kind`):

- `note`: pitch + time + non-empty unique `roleRefs` + `voiceRef`;
- `rest`: time + `voiceRef` (no pitch; `roleRefs` optional);
- `opaqueNotation` / `unsupportedRelation` / `UnknownSymbol`: explicit source
  states located by `measureRef` + non-negative `offset`, with `raw` source
  data preserved losslessly and NO fabricated pitch/duration/voice/roles.
  `UnknownSymbol` is a first-class variant (distinct from the others) for
  unrecognized source symbols.

Unknown event kinds are rejected (`unknown-event-kind`), never coerced.

## 4. Parser / validator

`ScoreIRDocument::from_json` and `validate_scoreir` produce structured
`ScoreIRDiagnostic`s (stable `ScoreIRDiagnosticCode` strings, JSON-path-ish
field, human message) - never only booleans. They reject:

- duplicate/malformed IDs and duplicate JSON keys (strict JSON reader);
- dangling and mistyped references (the score identity cannot be a
  reference target);
- missing required fields and unknown closed-schema fields (at every nested
  level, including written/sounding/opaque);
- derived-layer fields (`playbackTime`, `performance`, `transform`,
  `geometry`, `jianpu`, `rhythmicAnchor`, `visualAnchor`, `annotation`,
  `audio`) with their own `derived-layer-field` code, and out-of-scope
  RESERVED durable provenance metadata (`humanVerified`) with a distinct
  `reserved-field` code (never DerivedLayerField);
- unsupported schema versions / instance `$id` (`schema-binding-mismatch`,
  `unsupported-scoreir-version`);
- invalid/noncanonical/out-of-range rational times
  (`malformed-rational-time`, `rational-time-out-of-range`);
- negative offsets, nonpositive durations / `actualDuration`, fractional
  measure index, fractional/negative/out-of-range octaves, empty/duplicate
  `roleRefs`, malformed pitch fields, and unknown event kinds.

Canonical `parse -> serialize -> parse -> serialize` is byte stable for
semantically equal inputs even when fields are reordered at EVERY nested
level (object keys are canonicalized recursively); the serialization is
regenerated by the core (RationalTime fields re-serialized canonically), NOT
a raw echo of the input bytes. A document is returned only when there are no
diagnostics.

## 5. Real schema validation

The unit tests run a small local Draft 2020-12 subset validator (type /
required / properties / additionalProperties / items / minItems / enum /
const / pattern / minimum / maximum / uniqueItems / oneOf / $ref), loaded
from the public schema and its `$ref` targets via the catalog (offline, no
dependencies). The fixture must validate cleanly AND every negative input
must fail BOTH the schema and the core, so schema/core divergence is
detected.

## 6. Schema registration / fixture / harness

- `schemas/score/scoreir.schema.json`
  (`$id choirloom:score/scoreir/0.1.0`) and
  `schemas/score/scoreir-collection.schema.json` are registered in the
  source-of-truth catalog as Draft 0.1.0.
- `tests/golden/scoreir.samples.json` contains one full choral ScoreIR
  document: one choral part/staff, two voices, two roles, a pickup measure
  (`actualDuration` 1/3) plus a full measure, canonical RationalTime
  offsets/durations (0/1, 1/4, 1/12), F# vs Gb written-pitch distinction
  with octave, a shared-role note, a rest, and a genuine `UnknownSymbol`
  event.
- `dev.ps1 build|test|verify scoreir` (isolated build dir `build/dev/scoreir`,
  target `scoreir_tests`, exactly-one CTest guard `^scoreir_tests$`); verify
  emits `M0-005 ScoreIR schema verification passed.` and states the full M0
  milestone gate remains open.
